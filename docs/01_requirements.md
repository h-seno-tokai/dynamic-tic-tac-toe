# 01. 要件定義

最終更新: 2026-04-29

## 1. プロジェクト目的（再掲）

- Gobblet（ゴブレット）を題材にした「Dynamic Tic-Tac-Toe」をWeb実装
- GitHub公開・Web公開して就活ポートフォリオとする
- CPU対戦の最強モードは強化学習で実装し、機械学習の実績としてアピール

## 2. スコープ

### 2.1 含むもの

- ローカル2人対戦（同一画面・同一端末）
- CPU対戦（**10段階**の難易度）
- 日本語 / 英語（i18n 対応済み）
- PCブラウザ + スマートフォンブラウザ（モダンブラウザ最新版）
- BGM / 効果音
- アニメーション演出
- localStorage による戦績の簡易保存
- ダーク / ライト テーマ切替
- チュートリアル（v1 未実装・ルール説明画面で代替）
- ルールプリセット選択（**2種**: 3x3 クラシック / 4x4 巨大入り）

### 2.2 含まないもの

- オンラインPvP対戦
- ログイン・アカウント機能
- サーバ側ゲームロジック（クライアントのみで完結）

## 3. 機能要件

### 3.1 対局中

- 投了
- 待った（手戻し）
- 履歴の戻し / 進め
- 思考時間の表示
- アニメーション（駒移動・配置・覆い被せ）

### 3.2 対局後

- ローカル2人対戦の終局演出（「勝負あり！」）
- CPU対戦の勝利／敗北効果音
- 戦績保存（localStorage）
  - 保存内容: 対CPU難易度別の勝敗数、最終対局日 等
  - データ削除UIを提供

### 3.3 設定・周辺

- BGM ON/OFF + 音量
- 効果音 ON/OFF + 音量
- 言語切替（JA / EN）
- CPU難易度選択（**10段階**）
- 先手 / 後手選択（CPU対戦）
- ローカル2人対戦時のプレイヤー名入力 + アバター選択
- テーマ切替（ダーク/ライト、OS設定尊重）
- チュートリアル（初回オンボーディング + メニューから再アクセス可能）
- ルールプリセット選択（2種、後述）

## 4. 非機能要件

### 4.1 パフォーマンス

- CPU応答時間
  - 弱AI（難易度1）: 約1秒
  - 最強AI（難易度10）: 約10秒（モバイル環境含む）
- 初回ページロード: **10MB 以内**（ゲーム本体のみ）。ONNX Runtime WASM（~24MB）+ モデル重み（~9.6MB）はCPUモード選択時に遅延ロードされる。
  - うちモデル重み: ~9.6MB（float32、8×128ch ResNet）

### 4.2 対応環境

- ブラウザ: モダンブラウザ最新版（Chrome / Edge / Firefox / Safari）
- デバイス: PC + スマートフォン
- レスポンシブ必須・タッチ操作対応必須

### 4.3 言語

- 日本語、英語

### 4.4 アクセシビリティ

**目標: WCAG 2.1 AA レベル**（こちら側で決定）

- 対応するもの:
  - キーボード操作（タブ移動、矢印キーで盤面マス移動、Enter/Space で選択）
  - ARIA ラベル（盤面マス・駒・主要操作）
  - コントラスト比 4.5:1 以上
  - フォーカスインジケータの常時表示
  - `prefers-reduced-motion` 対応（アニメーション軽減モード）
  - ライブリージョンでのゲーム状態通知
- 対象外（優先度低）:
  - スクリーンリーダーでの完全動作検証
  - 専用ハイコントラストテーマ

### 4.5 セキュリティ

- ログイン無し・サーバ通信なし（モデル配信を除く）
- localStorage の扱いのみ留意
- 適切な CSP 設定

## 5. 制約条件

### 5.1 ホスティング

- **GitHub Pages**（確定）
- 制約:
  - 単一ファイル100MB制限 → モデル重みは数MB以内
  - HTTPS自動・カスタムドメイン可
  - GitHub Actions で自動ビルド・デプロイ

### 5.2 開発環境

- 学習: ローカルPC（RTX 2080 搭載）+ Python + PyTorch
- 推論: クライアント側（ブラウザ）

### 5.3 開発期間

- 非公開。約100時間規模を想定。

## 6. ゲームルール仕様

### 6.1 ルールプリセット（2種、確定）

| プリセット                 | 盤面 | 駒サイズ                  | 各サイズ駒数        |
| -------------------------- | ---- | ------------------------- | ------------------- |
| **3x3 クラシック**（既定） | 3x3  | 大・中・小（3段階）       | 各2個（合計6個/P）  |
| **4x4 巨大入り**           | 4x4  | 巨大・大・中・小（4段階） | 各3個（合計12個/P） |

ユーザーが完全カスタムでルールを組むUIは **提供しない**（複雑性回避）。

### 6.2 設計上の拡張性

完全カスタムUIは無いが、コード上は `GameRules` 設定オブジェクト駆動とし、**ハードコード禁止**。
理由: 将来プリセットを追加する場合や、AI 学習時に複数構成を扱う際に必要。

### 6.3 詳細ルール（確定）

- **勝利条件**: 縦・横・斜めいずれかに、自分の駒（トップが見えている駒）が **N 個** 揃ったら勝利（N = 盤面サイズ）
- **引き分け条件**: 合法手が一つも無い状態（手駒も無く、盤上の駒も動かせない）
- **覆い被せ**:
  - より **小さいサイズ** の駒の上にのみ覆い被せ可能（同サイズ・大きいサイズは不可）
  - 自分の駒の上にも被せ可能（標準 Gobblet 準拠）
- **盤外スタック**: サイズ別の残り駒数のみで管理（物理スタックの取り出し順制約は採用しない）

詳細は `06_data_model.md` 参照。

## 7. CPU・強化学習方針（要約）

詳細は `07_ai_design.md`。

- アルゴリズム: AlphaZero系（自己対戦のみ・完全教師無し）
- 学習: PyTorch + RTX 2080 でオフライン
- 推論: ONNX Runtime Web（ブラウザ）
- MCTS: TypeScript で自前実装、Web Worker で実行
- 1ネットワークから 10段階の難易度を派生（チェックポイント・シミュレーション数・温度で制御）

## 8. 確定事項 vs 未決事項

### 確定済み

- スコープ（オンライン無し・ログイン無し）
- 対応プラットフォーム（PC + モバイル / モダンブラウザ最新版）
- CPU応答時間（弱1秒 / 強10秒）
- 強化学習: AlphaZero系
- 推論ランタイム: ONNX Runtime Web
- ホスティング: GitHub Pages
- 戦績保存: localStorage
- テーマ切替: ダーク/ライト（OS設定尊重）
- チュートリアル/ルール説明画面: 実装する
- 多言語化: 日本語 / 英語
- アクセシビリティ: WCAG 2.1 AA レベル目標
- 初回ロード目標: 10MB 以内
- ルールプリセット: 2種固定（3x3 クラシック / 4x4 巨大入り）
- 完全カスタムUI: 提供しない（コード上は GameRules 駆動で将来拡張可）
- CPU難易度段階数: 10段階
- フロントエンドフレームワーク: React
- 詳細な技術スタック: `04_tech_stack.md` 参照
- アーキテクチャ: `03_architecture.md` 参照

### 確定（追加）

- ゲームルール詳細: 勝利条件 / 引き分け条件 / 覆い被せ / 盤外スタック仕様（6.3 参照）
- ルール選択: 2 プリセット固定（3x3 クラシック / 4x4 巨大入り）
- カスタムルール時の CPU: ユニバーサル CNN で同モデル流用
- ユーザーアバター: DiceBear Avataaars
- BGM: DOVA「Whip」by しゃろう
- SFX: 効果音ラボ統一セット
- CPU アバター: DiceBear Avataaars（seed: "cpu-robot"、固定）
- AlphaZero ネットワーク: 4×4×27 入力 / ResNet 8×128ch / 約2.4M params / ~9.6MB ONNX（float32）
- コーディング規約 / コンポーネント設計指針: `09_conventions.md` 参照
- リプレイ永続化: 不要（戦績のみ保存）

### 実装済み（完了）

- カラーパレット・タイポグラフィ: Tailwind CSS + CSS variables（ダーク/ライト対応）
- アニメーション: Framer Motion（spring / fade、`prefers-reduced-motion` 対応）
- 「勝負あり！」演出: PlayPage 内モーダルオーバーレイ（spring アニメーション + fanfare SFX）
- 結果表示: `/result` 独立ルートではなく PlayPage 内モーダル
