# 01. 要件定義

最終更新: 2026-04-29

## 1. プロジェクト目的（再掲）
- Gobblet（ゴブレット）を題材にした「Dynamic Tic-Tac-Toe」をWeb実装
- GitHub公開・Web公開して就活ポートフォリオとする
- CPU対戦の最強モードは強化学習で実装し、機械学習の実績としてアピール

## 2. スコープ

### 2.1 含むもの
- ローカル2人対戦（同一画面・同一端末）
- CPU対戦（**10段階**の難易度）
- 日本語 / 英語の i18n 対応
- PCブラウザ + スマートフォンブラウザ（モダンブラウザ最新版）
- BGM / 効果音
- アニメーション演出
- localStorage による戦績の簡易保存
- ダーク / ライト テーマ切替
- チュートリアル / ルール説明画面
- ユーザーによるゲームルール変更（盤面サイズ・駒サイズ構成）

### 2.2 含まないもの
- オンラインPvP対戦
- ログイン・アカウント機能
- サーバ側ゲームロジック（クライアントのみで完結）

## 3. 機能要件

### 3.1 対局中
- 投了
- 待った（手戻し）
- 履歴の戻し / 進め
- 思考時間の表示
- アニメーション（駒移動・配置・覆い被せ）

### 3.2 対局後
- ローカル2人対戦の終局演出（「勝負あり！」）
- CPU対戦の勝利／敗北効果音
- 戦績保存（localStorage）
  - 保存内容: 対CPU難易度別の勝敗数、最終対局日 等
  - データ削除UIを提供

### 3.3 設定・周辺
- BGM ON/OFF + 音量
- 効果音 ON/OFF + 音量
- 言語切替（JA / EN）
- CPU難易度選択（**10段階**）
- 先手 / 後手選択（CPU対戦）
- ローカル2人対戦時のプレイヤー名入力 + アバター選択
- テーマ切替（ダーク/ライト、OS設定尊重）
- チュートリアル（初回オンボーディング + メニューから再アクセス可能）
- ゲームルール設定（盤面サイズ・駒サイズ構成）

## 4. 非機能要件

### 4.1 パフォーマンス
- CPU応答時間
  - 弱AI（難易度1）: 約1秒
  - 最強AI（難易度10）: 約10秒（モバイル環境含む）
- 初回ロード合計サイズ目標: **10MB 以内**（モデル重み込み）
  - うちモデル重み: 数MB を目標

### 4.2 対応環境
- ブラウザ: モダンブラウザ最新版（Chrome / Edge / Firefox / Safari）
- デバイス: PC + スマートフォン
- レスポンシブ必須・タッチ操作対応必須

### 4.3 言語
- 日本語、英語

### 4.4 アクセシビリティ
**目標: WCAG 2.1 AA レベル**（こちら側で決定）
- 対応するもの:
  - キーボード操作（タブ移動、矢印キーで盤面マス移動、Enter/Space で選択）
  - ARIA ラベル（盤面マス・駒・主要操作）
  - コントラスト比 4.5:1 以上
  - フォーカスインジケータの常時表示
  - `prefers-reduced-motion` 対応（アニメーション軽減モード）
  - ライブリージョンでのゲーム状態通知
- 対象外（優先度低）:
  - スクリーンリーダーでの完全動作検証
  - 専用ハイコントラストテーマ

### 4.5 セキュリティ
- ログイン無し・サーバ通信なし（モデル配信を除く）
- localStorage の扱いのみ留意
- 適切な CSP 設定

## 5. 制約条件

### 5.1 ホスティング
- **GitHub Pages**（確定）
- 制約:
  - 単一ファイル100MB制限 → モデル重みは数MB以内
  - HTTPS自動・カスタムドメイン可
  - GitHub Actions で自動ビルド・デプロイ

### 5.2 開発環境
- 学習: ローカルPC（RTX 2080 搭載）+ Python + PyTorch
- 推論: クライアント側（ブラウザ）

### 5.3 開発期間
- 非公開。約100時間規模を想定。

## 6. ゲームルール仕様

### 6.1 デフォルトルール
- 盤面サイズ: **3x3**
- 駒サイズ: **大・中・小** の3段階
- 各サイズの駒数: **プレイヤーあたり 各2個**（合計6個/プレイヤー）

### 6.2 拡張性要件
**ハードコード禁止**。`GameRules` 設定オブジェクトでゲーム挙動を駆動する。
- 盤面サイズ可変: 3x3 / 4x4 / それ以上
- 駒サイズ段階数可変: 3段階 / 4段階（極大追加）/ それ以上
- 各サイズの駒数可変: 1〜N個

### 6.3 詳細ルール（未決・ユーザー単独決定事項）
- 勝利条件の正式定義（暫定: 盤面サイズ N の N目並べ）
- 駒の覆い被せ条件（同サイズ可？自分の駒の上に被せ可？）
- 盤外スタックの仕様

詳細は `06_data_model.md` 参照。

## 7. CPU・強化学習方針（要約）

詳細は `07_ai_design.md`。
- アルゴリズム: AlphaZero系（自己対戦のみ・完全教師無し）
- 学習: PyTorch + RTX 2080 でオフライン
- 推論: ONNX Runtime Web（ブラウザ）
- MCTS: TypeScript で自前実装、Web Worker で実行
- 1ネットワークから 10段階の難易度を派生（チェックポイント・シミュレーション数・温度で制御）

## 8. 確定事項 vs 未決事項

### 確定済み
- スコープ（オンライン無し・ログイン無し）
- 対応プラットフォーム（PC + モバイル / モダンブラウザ最新版）
- CPU応答時間（弱1秒 / 強10秒）
- 強化学習: AlphaZero系
- 推論ランタイム: ONNX Runtime Web
- ホスティング: GitHub Pages
- 戦績保存: localStorage
- テーマ切替: ダーク/ライト（OS設定尊重）
- チュートリアル/ルール説明画面: 実装する
- 多言語化: 日本語 / 英語
- アクセシビリティ: WCAG 2.1 AA レベル目標
- 初回ロード目標: 10MB 以内
- ゲームルール（デフォルト）: 3x3 / 大中小 各2個ずつ
- ゲームルール拡張性: 盤面サイズ・駒サイズ段階数・駒数すべて可変
- CPU難易度段階数: 10段階
- フロントエンドフレームワーク: React
- 詳細な技術スタック: `04_tech_stack.md` 参照
- アーキテクチャ: `03_architecture.md` 参照

### 未決（ユーザー単独決定事項）
- 勝利条件の正式定義
- 駒の覆い被せ条件（同サイズ可？自分の駒の上に被せ可？）
- 盤外スタックの仕様
- AlphaZero モデルアーキテクチャ詳細（入力チャンネル・バックボーン・ヘッド）
- コンポーネント分割の粒度（実装フェーズで決定）

### 未決（こちらと相談する項目）

- カスタムルール時の CPU 対応方針（同モデル流用 vs 簡易AI代替）
